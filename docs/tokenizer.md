# Tokenizer：从字节到可测量的 BPE

这是本仓库的教学规范，未声称与任何未提供的官方 handout 完全一致。顺序为 T1 → T2 → T3 → T4 → T5。先跑小例子，再考虑性能；`NotImplementedError` 表示明确的待实现工作。

## 统一接口与约定

- 基础 token ID 为 `0..255`，词表 `vocab[id]` 存储 `bytes`，基础条目始终保留。中文和 emoji 也从 UTF-8 字节开始，没有未知字符 token。
- `train_bpe(texts, vocab_size, ...) -> BPEModel` 接收有限的字符串集合/迭代器；不同字符串之间不统计相邻对。不要把输入集合无分隔地拼成一篇文本。
- `vocab_size` 是**总词表条目数的上限**，包含 256 个字节、实际创建的 BPE token 和特殊 token。它不是新增合并次数；不足 `256 + 特殊 token 数` 时抛 `ValueError`。没有可合并对时提前停止，可能达不到上限；频率为 1 的对也可合并。
- 同频时选择 `(left_id, right_id)` 按整数元组字典序最小的对。新 BPE ID 从 256 连续分配；每条 `Merge(pair, new_id)` 的位置就是 rank（从 0 开始），不按新 token 的字节长度排序。
- `BPEModel` 的 `vocab`、`merges`、`special_tokens` 和 `pretokenization` 保存全部编码语义；数据类和构造器已提供，不包含算法。模型在编码时不应被修改。
- `pretokenization="none"` 把每段普通文本当成一个单元。`"simple"` 使用下面的无损规则；模型保存这个选择，编码沿用它。
- `decode(ids, errors="strict")` 先拼接所有 token 的字节，再统一 UTF-8 解码。不对单个 token 单独解码；只支持 `"strict"` 或 `"replace"`。未知 ID 抛 `ValueError`；非法字节序列在 strict 模式下抛 `UnicodeDecodeError`。

## T1：字节分词器

**学习目标：** 分清字符、UTF-8 字节和 token，完成最基础的无损往返。

**输入输出：** `ByteTokenizer.encode(str) -> list[int]`；`decode(Sequence[int], errors=...) -> str`。例如 `"A" → [65]`，空文本对应空列表。

**前置知识：** `str` 与 `bytes`、UTF-8 变长编码、序列拼接、异常。

**亲手实现：** [byte_tokenizer.py](../src/lm_lab/tokenization/byte_tokenizer.py) 中两个 TODO。辅助构造器和常量已就绪。

**验收：** `python -m pytest -m t1 -q`；检查英文、中文、emoji、空文本、连续空格、换行及未见字符的准确 ID 与还原。未知 ID 和非法 UTF-8 必须按约定处理。

**常见错误：** 用字符码点当字节；逐个字节解码中文；擅自 strip 或规范化；悄悄忽略非法 ID。

**分层提示：** ① 比较 `len(text)` 和 `len(text.encode("utf-8"))`。② 在交互环境查看 `bytes` 迭代时产生的类型。③ 将全部整数恢复成一个字节串后再解码；保持错误策略可见。

## T2：最小 BPE 训练

**学习目标：** 把可手算的频率统计与替换步骤变成确定性的训练过程。

**输入输出：** `count_pairs(ids)` 返回相邻对到频率的字典；`merge_pair(ids, pair, new_id)` 返回新列表；`train_bpe(["abab"], 258)` 返回包含基础字节、`256: b"ab"`、`257: b"abab"` 和两个有序 merge 的模型。

**前置知识：** T1、字典计数、整数元组排序、循环游标、不可修改输入的意识。

**亲手实现：** [bpe.py](../src/lm_lab/tokenization/bpe.py) 中 `count_pairs`、`merge_pair`、`train_bpe` 的 `none` 模式；这一任务先使用 ASCII 和无特殊 token。

**验收：** `python -m pytest -m t2 -q`。`"abab"` 首轮 `(97,98)` 频率 2，次轮 `(256,256)` 频率 1；`"abac"` 的同频首选 `(97,98)`。`"aaa"` 中 `(97,97)` 的频率为 2，但合并只能输出 `[256,97]`。训练 `['a','b']` 不应出现跨字符串合并。空语料允许得到基础词表，容量不足应报错。

**常见错误：** 计数时排除重叠对；替换时又合并重叠位置；合并后不更新频率；同频依赖字典插入顺序；将目标容量当作新增 token 数。

**分层提示：** ① 先手写每一轮的 token 列表和计数表。② 将计数与替换拆开测试，关注替换游标应前进几格。③ 每轮在当前单元上重新计数，比较“频率降序、ID 对升序”，保存新 token 的字节和规则；小样本优先清楚而非快。

## T3：按 rank 编码与统一解码

**学习目标：** 使用已训练规则进行编码，理解训练频率与编码优先级的区别。

**输入输出：** `BPETokenizer(model).encode(text) -> list[int]`，`decode(ids) -> str`。编码每轮选择**当前序列里可用规则中 rank 最小的一条**，从左到右合并它的全部不重叠位置，再查找下一轮规则；不重新按频率训练。

**前置知识：** T2、规则查找、字节串拼接。部分测试使用手工模型，不必依赖训练器调试。

**亲手实现：** `BPETokenizer.encode/decode` 的无预分词、无特殊 token 情况。

**验收：** `python -m pytest -m t3 -q`。手工规则按序为 `b+c→256`、`a+b→257`、`a+256→258` 时，`"abc"` 必须编码为 `[258]`。这能区别“最左规则”与“最小 rank”。还要检查未见中文/emoji、跨 token 的 UTF-8 解码、非法 ID 和重复编码确定性。

**常见错误：** 使用最长 token 匹配或当前最高频对；按位置而非 rank 选规则；对部分 UTF-8 token 单独解码；编码时修改词表。

**分层提示：** ① 先列出当前相邻对中哪些在规则表里。② 把 rank 作为规则索引，选择最小可用项。③ 复用 T2 的不重叠替换，循环直到没有可用规则；解码只通过词表恢复字节。

## T4：预分词与特殊 token

**学习目标：** 保留真实文本全部信息，同时控制合并边界。

**输入输出：** `pretokenize(str) -> list[str]`；训练和编码增加相同的分段逻辑。`"Hi,  世界!\n🙂"` 的预分词结果为 `["Hi", ",", "  ", "世界", "!", "\n", "🙂"]`。

**前置知识：** T3、Unicode 字符分类、文本扫描、显式许可。

**规则：** `simple` 按字符的三类（Unicode `isalnum()`、`isspace()`、其余符号/标点）产生各类的最大连续片段；下划线属于第三类。相连的不同标点/emoji 可同属一个片段。片段拼接必须等于原文，不能丢空格、换行或规范化。每个片段内部独立应用 BPE；合并不跨片段。这个简单规则不是某个商业 tokenizer 的复刻。

**特殊 token 边界：**

1. 训练配置为非空且不重复的文字标记，如 `special_tokens=("<eos>",)`。特殊 ID 在实际 BPE ID 后连续分配，`vocab` 中存放标记的 UTF-8 字节。
2. 训练时先识别所有配置的标记，再对普通段预分词；标记作为边界，不进入普通对频率，也不与两侧合并。
3. 编码仅识别 `allowed_special` 显式许可的已配置标记，默认空集合：类似 `"<eos>"` 的文本按普通字节处理。许可未知标记时抛 `ValueError`。
4. 同一位置有多个获许可标记时取最长字面匹配；可在任何字符位置识别，不要求空白边界。先匹配特殊标记，再预分词普通段。
5. 不自动添加 BOS/EOS。特殊 ID 解码回原标记，不删除它。训练与编码的普通文本预分词规则相同；特殊许可策略按上述显式区别处理。

**亲手实现：** `pretokenize`；将它接入训练和编码；实现特殊标记的识别、容量预留、ID 分配和边界行为。

**验收：** `python -m pytest -m t4 -q`。覆盖空白/换行/标点保留、预分词不跨界、特殊 token 两侧隔离、默认字面文本、相邻标记及最长匹配，并检查训练/编码一致性。

**常见错误：** 使用会丢分隔符的 split；训练和编码使用不同规则；special 默认为控制信号；跨 special 合并；把标记当作一个 Unicode 字符；目标容量漏算特殊 token。

**分层提示：** ① 先测试 `"".join(pretokenize(text)) == text`。② 将特殊标记拆分与普通段预分词分为两步，训练/编码共用普通段逻辑。③ 用 `"a<eos>b"` 和连续标记画出合法边界，再检查任何 merge 都不越界。

## T5：保存、加载和测量

**学习目标：** 把模型表示变成可复现的编码器，区分测量工具就绪和算法实测。

**输入输出：** `save(path) -> None`；`BPETokenizer.load(path) -> BPETokenizer`；测量脚本产生 JSON。

**前置知识：** T4、JSON、文件编码、格式版本、数据指纹、计时噪声。

**文件格式（版本 1）：** 使用 UTF-8 JSON。根字段为 `format: "lm-lab-bpe"`、`version: 1`、`pretokenization`、`vocab`（ID 的十进制字符串 → 字节的十六进制字符串）、`merges`（按 rank 排列的 `{ "pair": [left, right], "new_id": id }`）和 `special_tokens`（原标记 → ID）。必须保留所有基础字节，合并输入必须已存在且合并字节内容一致，ID 不能复用；special 的 ID/字节应与标记一致。拒绝不支持的格式/版本或损坏的规则，抛 `ValueError`；缺少文件保留 `FileNotFoundError`。相同模型再次保存应得到相同内容，不写随机标识或时间。

**亲手实现：** `save/load`、格式校验和规范化保存。计时、样本、版本/硬件记录的脚本已提供；读取它并解释所测量的范围。

**验收：** `python -m pytest -m t5 -q`，然后全套 `pytest -q`。保存前后词表、rank、预分词、特殊许可及编码/解码一致；不支持版本和损坏图报错。重复训练、编码及保存内容确定。再运行 README 的两个测量命令，检查真实输出和还原结果。

**常见错误：** 直接 JSON 序列化 bytes；把 dict 键加载成字符串却继续当整数用；丢失 merge 顺序、预分词或 special；将 byte/sec 当 token/sec；把手写样本的成绩描述为真实数据性能。

**分层提示：** ① 先手工写出一个仅含基础字节的合法 JSON 表示。② 用 hex 表达 bytes，用数组保留规则顺序；分开做格式读取和模型校验。③ 在还原模型后复用现有编码器，保存前后跑同一组固定输入；测量前预热，多次计时并保存每次原始耗时。

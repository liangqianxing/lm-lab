# 学习路线

## 状态与共同验收规则

每个里程碑只使用 **未开始 / 进行中 / 已验证**。下表记录当前状态；接口、文档和测试就绪并不表示算法已验证。开始实现时改为“进行中”，通过相应行为验收并留下命令、代码版本、原始输出后才改为“已验证”。失败与暂缺证据要保留在记录中。

各阶段都需要：可重复的配置与随机种子、独立评测数据、推理检查、数值稳定性检查。对照必须采用相同输入与可比预算；随机实验记录多次运行的波动。性能结论只来自实际测量。当前没有官方 handout，因此不声明兼容任何特定课程或版本。

## 2. Systems

| 里程碑 | 状态 | 目标与依赖 | 验收标准 |
| --- | --- | --- | --- |
| S1 性能基线与瓶颈 | 未开始 | 依赖 B4；先在现有硬件做 CPU 基线，有 GPU 后测显存 | 记录吞吐、步耗时、峰值内存/显存、预热及同步方法；用 profiler 解释瓶颈，保留原始输出 |
| S2 GPU、Triton、FlashAttention | 未开始 | 依赖 S1 与可用 GPU；GPU 执行/访存、分块与融合 | 每项优化都有相同输入的正确性对照（遮罩、形状、前向、梯度与误差容限）及优化前后计时/显存；即使没有提升也如实报告 |
| S3 分布式训练 | 未开始 | 依赖 S2 与相应设备；通信、全局 batch、梯度累积 | 小实验对照单设备结果；验证梯度同步和有效 batch，区分吞吐与通信开销，检查各 rank 的恢复行为 |

无 GPU 时保留 GPU 实验为“未开始”，可先学习硬件概念；不启动付费计算，也不据此伪造硬件验收。

## 3. Scaling

| 里程碑 | 状态 | 目标与依赖 | 验收标准 |
| --- | --- | --- | --- |
| C1 资源估算 | 未开始 | 依赖 B4 与 S1；参数、梯度、优化器状态、激活、计算量 | 声明精度、batch、序列长度及估算假设；将参数量、内存与计算量估计和实际小实验对照，解释差异 |
| C2 小规模 scaling law | 未开始 | 依赖 C1；拟合、验证误差与不确定性 | 在可比数据/评测条件下改变模型规模、数据量和计算预算；保留实际计算记录，比较拟合与留出点，报告种子波动和外推范围/不确定性 |

拟合结果只能支持观测范围内及明示假设下的推断，不将少量小模型实验外推成确定的大模型能力结论。

## 4. Data

| 里程碑 | 状态 | 目标与依赖 | 验收标准 |
| --- | --- | --- | --- |
| D1 数据流水线 | 未开始 | 依赖 B1/B4；文本提取、编码、过滤、精确/近似去重、划分 | 每步记录输入输出量及来源许可；小例子检查误删；固定划分规则并检查跨划分重复与评测泄漏 |
| D2 可比数据实验 | 未开始 | 依赖 D1 与资源估算；处理策略消融 | 固定模型、训练 token/计算预算、评测集和种子；比较处理前后结果，报告重复检测的盲区、数据分布变化与波动 |

先固定评测来源和隔离规则；在分组去重/划分中避免同一文档片段跨集合。若实验顺序需要 Data 的干净语料，可提前完成 D1。

## 如何留下证据

每个实验复制 [实验模板](experiment_template.md)，把原始日志放在 `runs/`；文档只总结可追溯的发现。成熟库可在相应阶段作为明确标注的正确性对照，不替代自己的核心实现。基础检查与阶段功能验收分开记录。
